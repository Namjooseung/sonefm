# SoneFM 업무자동화 — 새 업무 유형과 새 앱 추가

## 1. 새 업무 유형(레시피) 추가 — 프로그램 수정 없음

업무 유형 하나는 **레시피 파일(JSON) 하나**입니다. 이미 있는 앱이 할 수 있는 일이라면 파일만 추가하면 됩니다.

1. `문서\SoneFM\platform\recipes\` 폴더에 메모장으로 `<이름>.json` 파일을 만듭니다. (UTF-8로 저장)
2. 아래 예시를 고쳐서 씁니다. 기존 유튜브 레시피(설치 폴더의 `recipes\youtube-video.json`)를 복사해서 고쳐도 됩니다.
3. 업무자동화에서 [새로고침]을 누릅니다. 업무일지 글자에 `keywords`의 낱말이 들어 있는 업무에 새 유형이 붙습니다.
4. 파일에 문제가 있으면 화면 맨 위에 "레시피 ○○을(를) 읽지 못했습니다: …"가 빨갛게 뜹니다.

```json
{
  "id": "schedule-check",
  "name": "편성 회차 확인",
  "summary": "날짜·시각의 프로그램과 회차를 편성표에서 찾아 보여준다",
  "keywords": ["회차 확인"],
  "inputs": [
    {"name": "date", "label": "날짜", "type": "date", "default": "{task.date}"},
    {"name": "hour", "label": "시각(6~22)", "type": "int", "from_text": "(\\d{1,2})\\s*시"}
  ],
  "steps": [
    {"id": "info", "app": "sonefm-schedule", "command": "lookup",
     "args": {"date": "{input.date}", "hour": "{input.hour}", "db": "{schedule_db}"}}
  ],
  "result": {
    "copy": [{"label": "프로그램 이름 복사", "text": "{info.data.label}"}]
  }
}
```

| 칸 | 뜻 |
|---|---|
| `id` | 영문 이름(겹치면 안 됨). 기본 레시피와 같은 id면 이 파일이 대신 쓰입니다 |
| `name`, `summary` | 화면에 보이는 이름과 설명 |
| `keywords` | 업무일지 글자에 이 낱말이 있으면 이 유형으로 분류(위 파일부터 순서대로) |
| `inputs` | 실행 전에 묻는 칸. `type`: `date`, `int`, `file`, `folder`, `string`, `text`. `default`(기본값), `from_text`(업무 글자에서 찾기), `remember`(지난번 값), `optional`(비워도 됨) |
| `steps` | 차례로 부를 앱 명령. `app`과 `command`는 각 앱의 `sonefm-app.json`에 있는 것만 쓸 수 있습니다 |
| `args` | 앱에 넘길 값. `{input.date}`(입력 칸), `{info.data.label}`(앞 단계 결과), `{today}`, `{home}`(문서\SoneFM), `{schedule_db}`(받은 편성) |
| `result` | 끝나면 보여줄 버튼: `open`(폴더·파일 열기), `copy`(글자 복사), `links`(https 주소 열기) |

**쓸 수 있는 앱 명령** (각 앱 설치 폴더의 `sonefm-app.json`에 전체 목록과 설명이 있습니다)

| 앱 id | 명령 | 하는 일 |
|---|---|---|
| `sonefm-schedule` | `lookup` | 날짜·시각 → 프로그램 이름, 회차, 제목용 이름(`label`) |
| `sonefm-schedule` | `month` | 한 달 편성 전체 |
| `sonefm-schedule` | `set-prep` | 송출 파일 준비 상태 바꾸기 (받은 편성 사본에는 쓰지 마세요. 편성 담당 PC 데이터에서만 의미 있음) |
| `radio2yt` | `make-video` | 송출 mp3 → 음악을 잘라낸 유튜브용 mp4 (+ 제목·설명 파일) |

## 2. 새 앱 추가 — 개발자 작업

새 기능이 지금 앱으로 안 되면 새 앱을 만듭니다. 플랫폼 프로그램은 고치지 않습니다.

1. 상위 폴더의 `APP_CONTRACT.md`(앱 규칙)를 읽습니다. 핵심:
   - 앱 폴더에 `sonefm-app.json`(앱 id, 실행 방법, 명령 목록)
   - `<실행 파일> <명령> --input 입력.json --result 결과.json`으로 실행되고, 결과 JSON을 남김
   - 종료 코드 0 성공 / 2 일부 건너뜀 / 1 실패, 진행률은 `@progress 35 메시지`
   - 개인 계정·개인 키 금지. 키가 필요한 기능은 키가 없으면 꺼지고 앱은 죽지 않음
   - 설치판 exe는 시작할 때 출력 인코딩을 UTF-8로, 처리 안 된 예외 금지
2. 설치 파일이 exe 옆에 `sonefm-app.json`을 복사하게 합니다. 설치하면 업무자동화가 자동으로 찾습니다.
3. 그 앱을 쓰는 레시피를 1절처럼 추가합니다.
4. 상위 `CLAUDE.md`의 앱 표에 한 줄을 추가하고, 앱 폴더에 `PLATFORM.md`를 씁니다.

## 3. 동작 확인 절차

### 개발 환경 (개발자 PC)

1. 각 앱 폴더에서 테스트
   - 편성표: `.venv\Scripts\python -m pytest -q`
   - 유튜브 편집기: `.venv\Scripts\python -m unittest tests.test_cli tests.test_youtube`
   - 업무자동화: `.venv\Scripts\python -m pytest -q` (옆 폴더에 두 앱의 `.venv`와 ffmpeg가 있으면 **실제 두 앱으로 유튜브 레시피를 끝까지** 돌리는 테스트도 함께 돕니다)
2. 업무자동화 실행: `.venv\Scripts\python -m hub` → [설정] → 앱 폴더에 두 앱 저장소 경로 → 앱 목록에 "· 개발"로 보이는지.

### 설치판 (업무자동화 PC)

1. 세 설치 파일 설치 → 업무자동화 [설정]에서 폴더 지정(앱 폴더는 비움) → 앱 목록에 두 앱이 "· 개발" 표시 없이 보이는지.
2. 문제해결 문서의 "직접 확인하는 방법"으로 편성표 `lookup`이 `"status": "ok"`를 내는지.
3. [업무 추가] → `유튜브 <시각>시 테스트` → [실행] → 실제 송출 mp3와 썸네일 → 결과의 mp4가 `문서\SoneFM\유튜브\`에 생기고 재생되는지.
4. `문서\SoneFM\platform\logs\platform.log`에 `화면 열림: {"bridge":true …}`.

**2026-11-15 확인한 것:** 개발 환경 전체(세 앱 테스트, 실제 두 앱으로 레시피 끝까지), 편성표·업무자동화 exe(PyInstaller 빌드) 실행과 편성표 exe 명령줄. **아직 못 한 것:** 이 PC에 Inno Setup이 없어 설치 파일은 만들지 않았고, 유튜브 편집기 exe의 `make-video`는 빌드하지 않아 확인하지 못했습니다.
